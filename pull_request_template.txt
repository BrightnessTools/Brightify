<!--(PULL REQUEST TEMPLATE)-->
IN GENERAL:
- Each pull request (PR) shall cover only one topic ("atomic" PRs).
- Change as little code as possible to make reviewing and merging easy.
- Include a `pytest` test in the `tests` directory if relevant.
- Ideally, test the code yourself before submitting a PR.

1. TITLE
- Keep it brief and descriptive. 
- Optional keywords to prefix:
    feat (new feature/calculation),
    fix (bug fix),
    perf (optimization),
    docs (documentation).
- Multiple keywords can be combined.
- Examples: 'fix, perf: MCPL reading loop', 'feat: coordinates rotation'.

2. DESCRIPTION:
Use the following three point format:

- What changed:
Summary of the code changes.

- Why it changed:
The scientific or technical motivation.

- How to test:
Briefly describe how it could be tested/tried out (e.g. which methods to call). 
If you have made a `pytest`, mention it here.

<!--(END OF PULL REQUEST TEMPLATE)-->
